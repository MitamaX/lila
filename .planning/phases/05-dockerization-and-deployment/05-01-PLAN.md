<task type="auto">
  <name>Task 1: Configure sbt-native-packager</name>
  <files>project/plugins.sbt, build.sbt</files>
  <action>
    Add the `sbt-native-packager` plugin to `project/plugins.sbt` (e.g., `addSbtPlugin("com.github.sbt" % "sbt-native-packager" % "1.10.4")`). 
    In `build.sbt`, ensure `JavaServerAppPackaging` is enabled for the root project (it appears to be already present, but verify compatibility with Scala 3.3.5 / sbt 1.10).
    Configure the packager to produce a staged output (`Universal / stage`) that can be copied into our multi-stage Dockerfile.
  </action>
  <verify>
    <automated>sbt stage -h || true</automated>
  </verify>
  <done>sbt-native-packager is configured and capable of staging the application.</done>
</task>

<task type="auto">
  <name>Task 2: Create Multi-stage Dockerfile with Stockfish</name>
  <files>Dockerfile</files>
  <action>
    Create a multi-stage `Dockerfile`. 
    - **Builder Stage**: Use an appropriate sbt image (e.g., `sbtscala/scala-sbt:eclipse-temurin-21.0.2_13_1.10.0_3.3.5`) to run `sbt stage`.
    - **Runtime Stage**: Use an `eclipse-temurin:21-jre` (or similar Java 21) base image.
    - **Engine Inclusion**: In the runtime stage, install Stockfish (e.g., via `apt-get update && apt-get install -y stockfish` or downloading the latest binary).
    - **App Setup**: Copy the staged application from the builder stage to `/opt/app`.
    - **Health Check**: Define a Docker `HEALTHCHECK` instruction using `curl -f http://localhost:9000/api/health` (or the equivalent API status endpoint).
    - **Entrypoint**: Expose port 9000 and set the entrypoint to the staged application script.
  </action>
  <verify>
    <automated>docker build -t lila-analysis-api:test .</automated>
  </verify>
  <done>Dockerfile builds successfully, creating an image containing the compiled app and the Stockfish binary.</done>
</task>

<task type="auto">
  <name>Task 3: Create docker-compose.yml</name>
  <files>docker-compose.yml</files>
  <action>
    Create `docker-compose.yml` defining three services:
    1. `app`: Uses the Dockerfile. Maps port 9000:9000. Configures environment variables for Redis (`REDIS_URI`) and MongoDB (`MONGO_URI`). Depends on `redis` and `mongodb` using `depends_on` with `condition: service_healthy`.
    2. `redis`: Uses the `redis:alpine` image. Includes a healthcheck (`redis-cli ping`).
    3. `mongodb`: Uses the `mongo:latest` image. Includes a healthcheck (`mongosh --eval "db.adminCommand('ping')" --quiet`).
  </action>
  <verify>
    <automated>docker-compose config</automated>
  </verify>
  <done>docker-compose.yml is valid and properly orchestrates the application and infrastructure.</done>
</task>

<task type="checkpoint:human-verify">
  <what-built>Full Docker environment with App, Stockfish, Redis, and MongoDB</what-built>
  <how-to-verify>
    1. Run `docker-compose up -d --build`

    3. Run `curl -X GET http://localhost:9000/api/health` to ensure the API is responding.
    4. Run `docker-compose exec app stockfish` and type `isready`, expecting `readyok`.
    5. Check application logs with `docker-compose logs app` for any connection errors.
  </how-to-verify>
  <resume-signal>Type "approved" if the environment is fully operational.</resume-signal>
